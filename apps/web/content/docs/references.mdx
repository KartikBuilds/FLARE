## Tooling this project is built on

- [Slither](https://github.com/crytic/slither) — Trail of Bits' static analysis framework for Solidity; the foundation of FLARE's extraction stage.
- [Foundry](https://book.getfoundry.sh/) — the local, offline toolchain (`forge`/`anvil`) used for FLARE's validation adapter.
- [solc-select](https://github.com/crytic/solc-select) — Solidity compiler version management, used during the compilation stage.
- [NetworkX](https://networkx.org/) — the graph library behind FLARE's dependency and fund-flow graph construction.
- [React Flow](https://reactflow.dev/) — renders the fund-flow graph in the analysis workspace.

## Standards and classification references

- [EIP-20: Token Standard](https://eips.ethereum.org/EIPS/eip-20) — the ERC-20 interface several transfer-logic detectors reason about deviations from.
- [SWC Registry](https://swcregistry.io/) — the Smart Contract Weakness Classification, a prior art reference point for how the wider community catalogs Solidity vulnerability classes (FLARE's taxonomy is narrower and specific to fund-lock/availability failures, not a replacement for SWC's broader scope).
- [Solidity documentation](https://docs.soliditylang.org/) — language semantics referenced throughout the detector specifications, in particular around `delegatecall`, `selfdestruct`, and the gas-stipend behavior of `.transfer()`/`.send()`.

## A note on citation practice

Every incident figure on this site links back to one of the sources above (or is marked
unverified when it doesn't). If a link above goes stale, please open an issue — broken
citations should be fixed, not quietly removed.
